GenSRT Video subtitles in any language — User Guide

Generate subtitles for any video, in any language, using a desktop app. No command line required.

This guide covers the GUI app. For batch processing, CLI flags, and the full set of tuning knobs, see the README on GitHub.

What you can do with it

Drop a video onto the app, click Generate SRT, and a few minutes later you have a subtitle file sitting next to your video. The subtitles can be in the original language of the audio, or translated into your choice of target language.

The same .srt file works in VLC, Jellyfin, Kodi, web browsers, and just about anything else that plays video.

Installation

Two options:

Option 1 — Use the standalone build. Download and install the latest release from https://github.com/mountlord/GenSRT/releases.

The first run will take a few minutes to download Whisper model weights (~800 MB); subsequent launches are instant.

Option 2 — Install from source. See the Installation section in the README on GitHub. You'll need Python 3.10+ and CUDA 12.8.

Either way, you also need:

  • An NVIDIA GPU with CUDA 12.8 installed (CPU works but is much slower)
  • An internet connection (for Google Translate; the Whisper model also downloads on first run)

The interface

The window has four areas:

Top bar — filename, full path of the currently loaded video, and project buttons (Load, New Project, Save, Save As, Config). The "Save The Children" link is a donation prompt; the rest of the app works without clicking it.

Video player (left) — drag a video here, or use the Load button. Standard playback controls.

SRT lines (right) — each subtitle line shows its start time, the text, and its end time. Click a row to seek the video to that point. Each row has a checkbox (for Split) and a pencil icon (for Edit).

Footer (bottom) — selectors that control how the next Generate SRT run will work:

ControlWhat it does
Source languageWhat language the audio is in (Auto-detect lets Whisper figure it out)
Target languageWhat language to translate the subtitles into
ModelWhich Whisper model to use. Includes built-in sizes (tiny through large-v3-turbo) and any custom models you've added. Pick New… to add a custom HuggingFace model. See Using a custom model below.
VAD On/OffVoice Activity Detection — filters out silence before transcription. Usually leave on.
Generate SRTThe big button. Starts the transcription job.
Burn SRTBakes the loaded subtitles into a copy of the video. See Burning subtitles into the video below.
FullscreenMaximises the video player.

These are per-job overrides. To change your defaults permanently, click the Config button in the top bar.

Generate your first SRT

  1. Drag a video file onto the player area. Or click Load and pick one from a file dialog. Supported formats: mp4, mkv, ts, m2ts, mts, m4v, mov, avi, webm.
  2. Set the languages in the footer if needed.
    • For Korean audio → Malayalam subtitles: source = Korean, target = Malayalam, engine = Google (GTX)
    • For English audio → English subtitles (transcription only): source = Auto-detect, target = English
    • For "keep it in the original language, don't translate": set source and target to the same language
  3. Click Generate SRT. A progress bar appears. The first run loads the Whisper model into your GPU's memory (takes a few seconds), then processes the audio. For a 20-minute video on an RTX 3060 Ti, expect ~1–2 minutes total.
  4. The SRT lines appear in the right pane once it's done. They're also written to disk next to your video. See File naming below.
  5. Play the video to preview the subtitles. GenSRT renders them directly in the built-in player as the video plays, so you can verify the result without switching to a separate player. Any edit you make in the right pane shows up in the player immediately — no need to save and reload to check your work.
  6. Review and fix anything that looks wrong (see Editing below) or just hit Save and move on.

Watching with subtitles

GenSRT writes two subtitle files next to your video: a .srt (the universal format) and a .vtt (the web format). Open the video in any player that supports subtitles:

  • PotPlayer — auto-detects sidecar SRTs
  • VLC — auto-detects, or Subtitle menu → Add Subtitle File
  • Jellyfin / Plex / Kodi — server-side; subtitles appear as a selectable track
  • Web browsers via HTML5 — use the .vtt directly as a <track> element. No conversion needed.

If you generated multiple language SRTs for the same video, media servers like Jellyfin will surface each as a separate track that you can switch between in the player.

Editing subtitles

GenSRT is fast and accurate, but transcription is never perfect. The SRT lines panel is a built-in editor for fixing things up before you commit the final file. The built-in player shows your edits live — every change you make to a line is reflected on screen immediately, so you can verify the result without switching to another player.

Click a row → seeks the video to that line and pauses, so you can hear what was actually said.

Edit a line — click the pencil icon on the right of the row. A modal opens with the text, start time, and end time, all editable.

Split a line — when one SRT line covers too much speech, you can split it into two. Check the row's checkbox, then click Split at the top of the right pane. A modal opens with two halves you can fine-tune.

Merge two lines — when speech got split across two rows but should be one subtitle, check the checkboxes on both adjacent rows, then click Merge. The two lines combine into one (their texts joined on separate lines within the merged cue). If you want a single flowing sentence instead, use the Edit modal on the merged line to clean it up.

Delete lines — check one or more row checkboxes, click Delete, confirm. Subtitle indices renumber automatically on save.

Save — writes back to the loaded .srt file (and the matching .vtt).

Save As — writes to a different filename / location. Next Save goes to the new path.

Burning subtitles into the video

Sometimes you want a single video file with subtitles permanently visible — for sharing on platforms that don't support subtitle tracks (WhatsApp, Telegram, etc.), or for viewers who don't know how to turn subtitles on in their player.

GenSRT can bake the loaded subtitles into a copy of your video. Click the Burn SRT button in the footer. It's disabled until both a video and an SRT are loaded.

What happens:

  1. A notification confirms the burn started. GenSRT runs FFmpeg in the background and gives you control back immediately — you can keep working in the app or even close it; the burn continues.
  2. A new file appears next to your source video named <video>_subbed.mp4. If that name already exists, GenSRT auto-versions to _subbed_1.mp4, _subbed_2.mp4, etc., so you never lose a previous burn by accident.
  3. The output is a standard .mp4 with the subtitles burned visibly into the picture. No subtitle track to enable, no separate .srt needed — the subtitles are part of the video now.

Burn time depends on video length and your hardware. A 10-minute 1080p video typically takes 1–3 minutes on a modern GPU.

Languages and engines

GenSRT supports any source language Whisper recognises (~100 languages). For translation:

  • Google Translate is the default and supports any → any translation. This is what you want for Malayalam, Tamil, Telugu, Bengali, Hindi, etc. Requires an internet connection.
  • NLLB-200 (Meta) and MarianMT (Helsinki-NLP) are offline engines, but they only translate to English. They're useful if you're transcribing Korean / Japanese / etc. into English and don't want to depend on Google.
  • None (passthrough) — keeps subtitles in the source language with no translation.

If you pick Marian or NLLB with a non-English target, the app will refuse with a clear message ("Target language 'ml' is only supported by the 'google' translation engine…"). Switch to Google or change the target to English.

File naming

Subtitles land next to the video with this naming convention:

Target languageFile written
EnglishMyVideo.srt
MalayalamMyVideo.ml.srt
KoreanMyVideo.ko.srt
HindiMyVideo.hi.srt
(any other)MyVideo.<lang>.srt

English stays unsuffixed for compatibility with files you already have. All other languages get an ISO 639-1 code suffix. This matches the convention used by Plex, Jellyfin, and Kodi — so multiple language tracks for the same video coexist cleanly.

When you drop a video that already has a sidecar SRT, GenSRT loads it into the right pane automatically. If both MyVideo.srt and MyVideo.ml.srt exist, the unsuffixed one wins by default — drag the language-suffixed file directly if you want to edit that one instead.

Known Limitations

GenSRT is a draft tool for serious subtitle work. The AI does the heavy lifting; you polish the result. A few things to know:

  • Indic-language source audio — the built-in Whisper models struggle with fast, dense speech in Indian languages, particularly news broadcasts with English code-switching. Output may contain hallucinated content that reads fluently but doesn't match the audio. For Malayalam specifically, the built-in models also drop large stretches of speech on long-form audio — see Chunked inference for fine-tuned models below for the v1.2 solution using vegam. For other Indic languages, generate a draft and verify against the audio before publishing.
  • Code-switching audio — recordings that mix multiple languages (e.g., English-heavy Hindi conversations) may produce inconsistent script output.
  • Music-heavy content — Whisper occasionally hallucinates subtitles over long musical passages. Use the editor to remove them.
  • Speaker overlap — overlapping speech from multiple speakers is transcribed as a single segment without speaker attribution.
  • Long videos — for videos over 60 minutes, monitor VRAM usage; consider splitting first if memory becomes an issue.

Tips

  • Whisper model choice matters for accuracy. The default large-v3-turbo is a good balance. For Korean (and other languages with subtle phonetic distinctions), large-v3 produces noticeably better results at the cost of being ~3× slower. Change this in Config → Transcription → model.
  • VAD off if VAD is eating speech. Voice Activity Detection occasionally filters out real dialogue (especially soft-spoken or accented audio). The footer toggle is the quickest way to try a run without it.
  • Auto-detect is usually fine, but explicit is faster. If you know the source language, setting it in the footer skips the detection step and saves a few seconds per file.
  • Save As is your "make a copy before editing" button. Hit it before you start editing if you want to preserve the original Generate output.
  • Config changes propagate live. When you save settings in the Config modal, the footer selectors update immediately — no need to relaunch.

Using a custom model

The default Whisper models (tiny through large-v3-turbo) are general-purpose and work well for most languages. For some languages, though, a model fine-tuned specifically on that language can produce dramatically better results. GenSRT lets you add any faster-whisper-compatible model from HuggingFace and use it like the built-in models.

To add a custom model:

  1. In the footer, open the Model dropdown.
  2. Pick New… at the bottom of the list.
  3. In the modal, paste the HuggingFace repo ID — for example smcproject/vegam-whisper-medium-ml-int8_float16 for a Malayalam-tuned model.
  4. Click Validate & Add. GenSRT checks that the model exists on HuggingFace without downloading the weights (a 1-2 second check), then adds it to your model list.
  5. The new model is now selected. Click Generate SRT as usual — the first run downloads the weights (a few minutes for ~1 GB), subsequent runs are instant.

What kinds of models work? Look for HuggingFace repositories tagged for CTranslate2 or faster-whisper, or with names ending in -ct2, -faster, or -int8_float16. Standard HuggingFace Transformers Whisper models need a conversion step first and won't load directly.

Your custom model list is saved in gensrt-known-models.json next to the main config file, so it survives across sessions. Models also live in %USERPROFILE%\.cache\huggingface\hub\ once downloaded — they're shared across HuggingFace tools, so a model you downloaded for another project is already available to GenSRT.

Chunked inference for fine-tuned models

The built-in Whisper models (tiny through large-v3-turbo) were trained on long-form audio. They handle 30+ seconds of continuous speech cleanly in a single pass.

Community fine-tunes — Whisper models that someone has retrained on a specific language like Malayalam — are usually trained on short isolated phrases from corpora like Mozilla Common Voice. When you feed those models long-form audio, the model transcribes the first phrase (~6-8 seconds) and effectively stops. The rest of the audio is silently dropped from the output.

GenSRT 1.2 solves this with chunked inference. Instead of passing the whole audio to the model in one call, the audio is sliced into ~5-second pieces along natural silences, each piece is transcribed independently, and the per-chunk results are assembled with their original timestamps preserved. Malayalam users with vegam see roughly 2-3× more transcribed content compared to running the same model without chunking.

You don't need to opt in. When GenSRT detects you've selected a fine-tuned Whisper model (vegam variants are auto-detected; any custom model added via New… is treated as fine-tuned by default), the chunked-inference path runs automatically. Built-in Whisper models continue to use the standard single-call path.

The cost is real but bounded: chunked inference is roughly 2× slower than single-call inference, because each chunk is a separate model call with its own overhead. In practice this means ~2 minutes per 3-minute clip on a modest GPU instead of ~1 minute — a trade-off that buys you usable Malayalam subtitles in exchange for a longer wait.

A note on the � character in output

If you see the Unicode replacement character (�) at the end of a subtitle line, this is a signal from the underlying Whisper model that it stopped generating output mid-character. Whisper's tokenizer works on UTF-8 bytes, and Indic scripts use 3 bytes per character; when the model emits its end-of-segment token after only 1 or 2 of those 3 bytes, the decoder produces � to mark the incomplete sequence.

The transcribed text before the � is still accurate — only the final character of that segment is incomplete. This is a model limitation, not a GenSRT defect, and is most visible with fine-tuned models on dense speech. GenSRT shows the � as-is rather than hiding it, so you know which cues to spot-check during editing. If you see frequent � markers with a particular model, consider raising an issue with the model's maintainers.

Troubleshooting

"CUDA not available" or transcription is very slow.
The CPU fallback works but is much slower than GPU. Confirm CUDA 12.8 is installed (nvidia-smi should show your GPU). If you don't have an NVIDIA GPU, CPU mode is expected to be slow — a 20-minute video might take ~30 minutes instead of ~1 minute.

Video won't load (file with Korean / non-ASCII characters in the name).
Known issue with the embedded video player. Workaround: rename the file to use ASCII characters in the filename. The transcription itself handles all languages fine — it's just the player widget that's picky about filenames.

The SRT file appears next to the video, but the right pane is empty.
Check the engine selector in the footer. If you picked Marian or NLLB with a non-English target, the job fails silently in some setups. Switch to Google.

Subtitles appear slightly before the speaker actually starts speaking.
Lower vad_speech_pad_ms in Config → VAD & Subtitle Timing. Default is 200 ms; try 100 ms.

Whisper hallucinated text in silent sections.
Raise vad_threshold in Config → VAD & Subtitle Timing. Default is 0.5; try 0.6 or 0.7.
